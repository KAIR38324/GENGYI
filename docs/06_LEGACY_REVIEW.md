# 旧方案可复用的经验与必须防止的错误

本文件为插件的回归与验收依据。旧 F-R3 方案仅作为历史资料，不是本次插件的图块源，也不是已获用户认可的布置模板。

## 1. 最关键的图块来源错误

对旧 `changing_room_F.dxf` 的独立检查显示：模型空间共有 3707 个实体，`INSERT = 0`。块表只有模型/图纸空间、标注箭头与匿名尺寸块，没有用户的设备块定义。设备是代码自行绘制的线、多段线、圆和椭圆。

旧 `F_R1_symbols.py` 也明确将其定义为示意平面符号。旧 `preview_F_R1_symbols.py` 的左栏虽然写“原图符号”，实际调用的是旧 `export_engineering.equipment_primitives`，并非从用户原 CAD 提取。该对比图不能继续作为“原图块”的证据。

由此形成的实现要求：

1. 每个设备块必须记录来源类型、来源文件/块名、版本及单位；没有原块时明确标为据图重建。
2. 完成 CAD 布置后，实体应为可选择、可编辑、可更新容量数据的原生块参照，不以几千条互不关联的线段冒充设备块。
3. 原块导入要查实际尺寸、基点、方向和操作面，不能只核对外框长宽。
4. 自动布置、正交拖动、旋转、复制、删除及撤销之后，设备参数和图纸实体必须仍能互相对应。

## 2. 必须转成验收用例的历史问题

| 历史问题 | 已有证据 | 插件应采取的检查 |
| --- | --- | --- |
| 把 48 总格误当 48 人 | 最新标准柜每面 8×3=24 格，两面共 48 格，一人两格，因此 24 人 | 设备目录分别存 `persons`、`compartments_per_side`、`compartments_total`；参数切换后同时验证 |
| 用立面门数替代平面模数 | 一更柜 1140×500×2095，3 列×4 层；鞋柜 8 列×3 层×2 面 | 平面、立面、统计各用自己的数据，不能按总格数沿长边均分 |
| 只检查关门外包 | 旧女一更相向柜前净距 950；1140/3 的名义 380 门叶与固定人体位置存在约 30 的交叠反例 | 真实柜门叶片、下层取物和人员侧站策略纳入可选动作检查；需要错时让位时不得仍使用未经验证的同步时间 |
| 移门没有完整收门检查 | 女一更 900 单扇向北收拢，只有 525 直墙可用，缺 375；旧门扇算法对 sliding 返回空集合 | 平开门检查扫掠，移门检查全开停靠、轨道、墙角及相邻柜体；不可跳过某门型后给出“通过” |
| 人能走到设备侧面便当成可以操作 | 旧洗脱机净侧操作位整体在机器右侧，距出衣口中心约 1210；机前至折台约 900 | 操作区绑定真实前面/出衣口；需能完成开门、卸衣、接车，不只验证点可达 |
| 设备位数与成人有效位混用 | 旧 5 个五龙头池共 25 龙头，实际人体排布仅 13 个工作位置 | 硬件名义位数与有效操作位分别展示，吞吐用后者；平面重排需重算 |
| 静态容量当成吞吐证明 | 600 固定鞋位不代表 600 人同时换鞋；旧单向算法的完成时间依赖批次时长 | 输入在册人数、当班人数、交接重叠、批次/使用时间；先实现容量，不把面积估算自动宣称为完整班次验证 |
| 双层储物当成双倍跨柜能力 | 两柜叠放可有 48 人储存位，但占地、取物方式与可跨位置不同 | `storage_capacity`、`accessible_capacity`、`crossing_capacity` 分开；48 人叠柜不自动成为 48 人跨柜位 |
| 只求闭合矩形不查脏净旁通 | S 形外观不能证明员工必须跨柜，周边 1000 间距可能形成绕端路线 | 以实际柜体/连接/边界作障碍，检查脏侧与净侧在不跨柜的步行图上不连通；提供可定位的旁通路径 |
| 连接转角重复计容 | 圆角、封板或无柜格的接口构件也可能被作为模块统计 | 柜体、转角和封板分别建类型；未明确具备配对储物位的构件容量为 0 |
| 柜前有格位却无真实分配 | 配对容量仅算术相加，没有员工号与脏净两侧的对应关系 | 同一员工两格必须成对、无重号、能从正确一侧到达；复制和调整后重新分配 |
| 仅核对房名即宣称功能齐全 | 旧图未完整落实原总表中的金检门、更衣镜、主洗手皂液等 | 项目设备总表逐项映射设备类型、块、数量和状态；不能由房间名字推断全部设备存在 |
| 未闭合衣物周转 | 旧洗衣计算排了洗/烘/折，未同时解决干净衣物存放及领用时点 | 二更挂位不能默认兼作全厂 600 套净衣仓库；工装、常服、脏衣和备用品的用途分别标记 |

这些案例有不同证据强度。例如约 30 mm 的门叶/人体交叠是基于名义门宽的模型反例，并非已经实测该成品柜必定无法使用。验收应在真实块和实物参数确定后运行，不应把所有历史反例强行转成固定的空间加量。

## 3. 旧面积与时间数字应如何使用

旧 F-R3 几何复算得换鞋约 115.8417 m²、洗衣约 22.4017 m²，功能及必要走道净面积约 558.4371 m²。这些仅说明该重建方案在其边界和对象定义下的面积算术一致；不能证明符号正确、操作成立或新矩形也能容纳同样人数。

用户此前说明原换鞋方案约 135 m²，可服务 600+ 人。这是有价值的项目参照，应与原图、柜体组成、周边间距、叠柜比例和人员使用节拍一起保存。插件的估算模块应输出条件及范围，矩形精排后再给出实际摆放容量和未解决项。

旧单向进入算法在其假设下复算约 65.82 分钟，鞋阶段批次延长时明显变化；其数值不应硬编码进插件。600 在册与 300 当班、男女 1:1 是本项目输入示例，并非所有项目的固定值。

## 4. 本轮已经明确的边界

- 保留用户跨柜换鞋方式。不得把旧审核曾建议的“新增连续步行通路/应急开口”作为算法默认硬要求；新插件检查的是用户指定的日常脏净转换和不能绕柜的拓扑条件。
- 本任务是柜具布置插件及其开发交接。原布局的房间功能不得因算法方便被静默删除，也不得自动增加妇卫等候、妇卫处理、洗衣附属间等用户已删除的房间。
- 本项目示例保持无淋浴、右上进入、右向左、南侧车间、北侧贵宾、磨刀向南。柜具核心算法应可在其他矩形和方向中复用，不将这个楼层的绝对坐标硬编码。
- 边界柜距所选矩形边界 1000 是本次新增明确规则。处理端部闭合、隔离构件和不允许绕柜时，不能偷改该距离、把封板当作柜子偷偷压线，或在无法闭合时仍报告合格。

## 5. 允许继承的内容

可以继承原始设备表、用户最新人数与柜型规则、已注明前提的计算公式、原图的 S 形连接形式，以及上述独立审查方法。旧生成 CAD 可保留在明确命名的历史目录作负面样例。

以下内容应重新建立：原块库及来源记录、标准/定制鞋柜的列模块、转角接口、脏净面向、员工配对格位分配、矩形候选生成、周边及排间几何检查、不可绕柜拓扑检查、人工拖动后的实时统计与撤销机制。

后续本地 Codex 的成果应展示“已通过哪些实际用例、还有哪些参数未确认”，而不是沿用旧文件中的 `pass` 字样推断全部要求已经满足。
