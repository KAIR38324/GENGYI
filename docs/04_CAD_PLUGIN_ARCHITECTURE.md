# CAD 插件技术与交互契约

更新：2026-11-17。本文是交给本地 Codex 的开发要求，尚不是已经完成或通过宿主测试的插件说明。工程容量与几何计算以 `02_SHOE_GEOMETRY_AND_TOPOLOGY.md`、`03_CAPACITY_AND_AREA.md` 为准。

## 1. 首次开发先完成宿主识别

本轮用户已补充“CAD2024”，现按 AutoCAD 2024 Windows x64 配置，托管 API 为 R24.3，目标框架为 .NET Framework 4.8。具体产品名、补丁和安装环境尚待真实宿主的 `GYENV` 输出核查；不再重复询问已指定的 2024 主版本。开发工程、依赖和加载步骤见 [08_DEVELOPMENT.md](08_DEVELOPMENT.md)。若后续实际宿主是其他品牌或平台，以真实识别结果另建适配器。

本地 Codex 应在用户指定的开发目录和已安装 CAD 环境内完成：识别宿主名称、版本及补丁；核对该宿主支持的插件接口；确定 SDK 引用路径、CPU 架构和目标运行时；运行一个只创建临时演示块的加载验证。若这些信息无法由本地环境取得，只问一次具体的 CAD 品牌和完整版本号，不重复询问已经给定的人数和设备尺寸。

Autodesk 官方资料在检索日已按补丁区分运行时：AutoCAD 2026 至 2026.1.1 的文档列 `.NET 8`，2026.1.2 及以后列 `.NET 10`；AutoCAD 2025 创建项目指南也区分 2025 至 2025.1.3 与 2025.1.4 及以后。因此“AutoCAD 2025 以后全部编译为 net8.0”不可靠，应以实际安装版本的 SDK 和补丁文档为准。[A1][A2] 国产 CAD 另查其官方 SDK，不声称与 AutoCAD 二进制通用。

## 2. 工程分层

| 模块 | 负责内容 | 不应依赖的内容 |
| --- | --- | --- |
| `Domain` | 柜型、格数、人位、源证据、边界、实例、候选、检查结果 | CAD 的 ObjectId、窗口对象 |
| `Geometry` | 毫米坐标、正交变换、轮廓并集、距离、碰撞、自由空间连通性 | DWG 读写、UI 事件 |
| `Layout` | 预估、S 形候选生成、连接柜组合、搜索剪枝、排序去重 | 已经打开的 CAD 文档 |
| `Validation` | 容量、双侧可达、跨柜点、端部绕行、1000 mm 边界距离、原块来源 | 绘图表现层的“看起来通过” |
| `CadAdapter.<Host>` | 读取边界/块、单位变换、块导入、图元写入、撤销、原生编辑监听 | 食品工艺规则的硬编码副本 |
| `UI` | 人数表单、候选列表、拖动、统计、异常定位 | 直接从后台线程修改 CAD 数据库 |
| `Persistence` | 图纸内元数据、配置版本、候选 JSON、导出统计 | 云端账号、外部服务 |

建议用 C# 编写与宿主无关的核心；目标框架由第一步识别结果决定。可以单独多目标编译或使用兼容的核心项目，但不要把 CAD DLL 传递引用进几何测试项目。算法输入输出用版本化 JSON，方便当前参考计算与后续 C# 实现比对。界面优先宿主内停靠面板；AutoCAD 适配可使用 `PaletteSet`。[A3]

所有功能在本地完成。导入原块、读取用户选择的矩形、生成方案和统计不需要上传公司图纸，不默认扫描整盘或公司网络目录，不把项目资料自动写回公开仓库。

## 3. 原始图块接入是独立的开发阶段

### 3.1 来源状态必须进入数据

每个柜型及其 CAD 资源至少记录：`symbolSource`、`sourceFileHash`、`sourceBlockName`、`sourceUnits`、`sourceEvidence`、`reviewStatus`、`geometryVersion`。其中：

| `symbolSource` | 含义 | 允许显示的结论 |
| --- | --- | --- |
| `original_cad` | 从用户原 DWG/DXF 或其导出块文件导入 | 完成核对后可显示“原块复用” |
| `image_reconstructed` | 依据本仓库原截图重建的块 | 显示“据原图重建，待样式核对” |
| `legacy_generated` | 旧方案中的自绘示意符号 | 仅作问题回顾，不可作默认生产图块 |

本仓库现有的图片可以用于核对样式及重建，但图片不包含原 CAD 的块定义。旧 F-R3 DXF 的设备是散线示意，不能从那里建立所谓“用户原块库”。历史符号对比图中即使出现“原图符号”字样，也不能覆盖这一来源事实。

### 3.2 导入向导

1. 用户选择一份本地 DWG/DXF 或从当前图纸选择一个块实例；仅读取其授权选择的资源。
2. 列出设备块名称和预览，识别嵌套块、动态属性、可见性状态、属性文字、线型及单位。未知单位时，利用已确认的 2000 mm 鞋柜长度校准，并把比例记录下来；不得静默猜测。
3. 将该块绑定到柜型，指定基点、柜长轴、正面、脏侧、净侧、占地闭合轮廓、操作带、连接端口和允许的旋转。没有占地轮廓时先让用户确认从原块提取的轮廓，不能把包含文字/尺寸线的整体 `Extents` 当占地。
4. 从源块记录实际外形与 2000 × 600 等参数是否一致。尺寸冲突须显示原块测量值和参数表值，不通过拉伸伪造一致。
5. 预览水平和垂直实例、常用比例图面、两侧操作方向；保存绑定与证据来源。设备块最终以宿主原生块参照插入。AutoCAD 的 `BlockReference` 对应 INSERT，其变换应统一纳入占地与方向计算。[A4]

保留源 DWG/DXF；CAD 导入副本独立命名，防止覆盖当前图纸同名但不同内容的块。采用命名空间加短内容哈希，维护原名到导入名的映射。同名同内容可复用，同名不同内容必须区分。嵌套块也进行依赖解析；缺失外部参照、代理对象或宿主不支持的实体应给出具体缺项，不悄悄炸开或丢弃。

动态块须存有效源定义名、选定可见性状态和参数值。统计依据有效柜型配置，不以 `*U...` 匿名块名推断容量。仅允许已经证明与真实产品对应的动态参数；不假定“长度可拉伸”等于“柜位容量可线性增加”。

### 3.3 12、18、24、48 人型的生成边界

24 人双面柜按每侧 8 列 × 3 层，一人配脏净两格。12 人和 18 人型按同一名义 250 mm 列节距减少到 4 列、6 列；需要改变内部格线数量及对应细部，不能把 24 人块沿 X 非等比压缩成一半或四分之三。实际边框、圆弧转角、端部模块以原图和确认的定制方式为准。

48 人叠柜在平面只占一个 2000 × 600 落位组，物理柜模块为两个，名义高度 1200 mm；应有可辨认的“2 层叠放 / 48 人”属性或注记。不能把它画成两个重叠 INSERT 再重复统计，也不能将它自动视为两个跨柜操作位置。双层柜是否承担跨越转换、是否通过相邻低柜转换，以及两侧各层取放可达性，均由布局规则验证；没有已定义的转换路径时，不能仅靠 48 的标签宣告可用。

### 3.4 样式一致性

保留原块主要线条、格线、端部和设备内部符号；原块中已有的文字方向、门向及非对称细部应随正确变换处理。镜像默认关闭，因为镜像可能交换脏净侧和文字方向；若允许镜像，必须同时变换工艺侧别并重新验证。图块导入所需的等比单位换算与制造尺寸的非等比拉伸是两种操作，后者默认禁止。

图层按设备轮廓、内部细线、房间边界、尺寸、文字、操作检查、工艺侧别分别设置。用户原块颜色与线型优先保留，检查覆盖层单独控制。避免以实心填充盖住原块。模型空间按实际毫米尺寸绘制，不通过布局空间或巨大后置图框修饰错误模型。

## 4. 主工作流与命令建议

| 操作 | 建议命令 | 用户看到的结果 |
| --- | --- | --- |
| 初始配置/原块绑定 | `GYSETUP` / `GYBLOCK` | 设备库和来源状态、单位及实际尺寸 |
| 输入人数预估 | `GYESTIMATE` | 柜型组合、柜投影下界、方案面积范围及假设 |
| 选择矩形并生成 | `GYLAYOUT` | 多个不同 S 形候选及各自容量/问题 |
| 正交拖动/连接调整 | `GYDRAG` | 实时柜位、连接关系、距离和缺口更新 |
| 校核 | `GYCHECK` | 几何、卫生分隔、容量、原块来源分别结论 |
| 统计/重新识别 | `GYSTATS` | 已布置、有效、待布置和异常实例定位 |

选择矩形支持闭合四边多段线或两角点，并允许矩形在当前 UCS 中旋转。先将 CAD 坐标映射到局部正交布局坐标，核心算法用毫米计算，再还原到 WCS；不得把世界 X/Y 轴强加给旋转的房间。检测非矩形、非共面、零面积和带弧边界并给出具体原因。门口、柱、固定设备和不可占用区作为显式约束输入；不要从原图截图自动猜门口坐标。

默认项目参数可以预填单班 300、在册 600、男女人数 1:1；换鞋和一更按确认的在册储存需求，二更按当班需求。备用系数应显式显示，不能悄悄把 600 改成 660。首版必须完整覆盖换鞋间、一更、二更及男女子房间切换。各模式均有独立矩形、人数、设备库、候选生成、拖动、落图和统计；一更和二更不能仅提供数据或手动接口。房间模式契约见docs/07_ROOM_MODES.md。

## 5. 自动候选生成与状态

自动生成按 S 形组合枚举横柜段数、纵向连接柜类型、转折左右顺序、12/18/24 混合补齐和允许的叠放位置。纵向连接必须是有真实占地和容量的柜体实例，不能画一根连线并当作连接柜，也不能让横竖柜在角部重叠来虚增容量。

每个候选保存：实例清单、脏净两侧种子位置、柜体/封闭构件并集、柜距边界、最窄实际操作带、双侧可达的人位、跨柜转换位置、数量汇总、占用尺寸、错误及警告。检查顺序宜为单位与参数 → 边界/碰撞 → 几何连接 → 可达与隔离 → 容量 → 排序。禁止仅依靠设备外包面积或点状人模型宣布方案满足要求。

边界柜默认距选定边界 1000 mm；这个留空带应按实际空间参与连通性检查。若 S 形柜两端都离边界而周边地面连成一圈，人员能绕端到另一侧，该候选必须标为“不满足跨柜唯一转换”。需要的固定阻隔、柜端封闭及接口必须显式存在、单独统计并与原方案对应，不能靠把人行网格做粗而漏掉绕行路径。该校核专指本项目脏净分隔，不自动扩大为整栋建筑疏散结论，也不据此新增应急走道。

相同构型的微小平移不应占满候选列表。几何签名应包含柜型、离散朝向、相对位置、连接图和入口侧，按容差归一后去重。镜像只有在入口、脏净侧、边界约束完全对称时才可合并。排序先满足硬约束及目标人位，再比较实际占用尺寸、剩余空间连贯性、无效人位、柜型复杂度和操作条件。不得通过把“超额容量”得分调高来让拥挤无效方案胜出。

候选至少区分“有效候选”“几何可放但规则待满足”“无可行候选”。目标展示 3–8 个真正不同的有效候选；若只有 1 个或没有，应如实显示数量及限制原因，不造假候选。生成过程应可取消，后台计算只处理数据快照；CAD 读写在宿主要求的文档上下文完成。

## 6. 拖动与实时反馈

默认相对布局局部坐标正交，朝向为 0°、90°、180°、270°。允许切换自由模式，但非正交实例需单独提示，不能继续使用专供正交矩形的近似碰撞算法。拖动支持端口吸附、共线对齐、边界 1000 mm 吸附、成组移动整条 S 形段及锁定已确认实例。吸附不得拉长柜体来补连接缺口。

拖动预览用临时图形，颜色与提示分清碰撞、越界、边界距不足、绕端、容量损失和原块未核。AutoCAD 的 `DrawJig` 可提供独立于自定义实体的拖动输入和图形预览；具体适配仍应在目标宿主测试。[A5] 鼠标移动不应持续创建数据库实体。放置时验证最终位置；不满足硬约束时保留为可见的“未通过草案”或回到原位置，必须给出明确状态，不能让违规柜位计入已满足人数。

推荐常驻统计：

| 字段 | 定义 |
| --- | --- |
| 目标人数 / 含备用目标 | 用户人数与显式备用策略分别列出 |
| 地面柜组 / 实体柜模块 | 双层叠放为 1 组、2 个模块 |
| 名义人位 / 有效人位 | 前者按柜型算；后者须具备完整脏净配对及可达条件 |
| 已分配人数 | 只有建立人员/编号分配后才使用这个词；没有分配时显示“已布置有效人位” |
| 仍缺人位 / 余量 | `max(0, 目标−有效人位)` 与 `max(0, 有效人位−目标)` 分别显示 |
| 尚需柜子 | 固定柜型时显示向上取整柜数；混合柜型时给出具体补齐组合，不能给一个没有柜型说明的数量 |
| 无效或待核柜组 | 点击定位实例，并列具体原因 |
| 面积 | 所选区域面积、柜体投影并集面积、实际占用外包和未利用面积分别展示 |

## 7. 图纸内持久化与原生编辑

每个实例须有稳定实例 ID、柜型 ID、布局 ID、来源哈希、叠放数、容量及配置版本。布局级记录存在图纸内，配置文件作为可导出副本，不能依赖界面内存才能重开恢复。可见属性保留必要的人位/柜号，完整数据由宿主支持的扩展字典等机制保存；避免每个格子产生独立巨大元数据。

原生 MOVE、COPY、ROTATE、ERASE、UNDO、REDO、夹点及动态块编辑也必须更新统计。AutoCAD 提供数据库对象新增、修改、删除、撤销重加等事件，但事件应作为重新校核的触发器，不能在每一次回调内直接递归修改对象。[A6] 推荐事件标脏、去抖、在安全的命令结束/空闲上下文重读；COPY 后新实例获得新 ID，原块炸开后标为脱离管理，不能继续按旧缓存累计。多文档切换应切换对应状态，关闭文档解除事件订阅。

“批量生成”“接受候选”“删除整组”各对应一次清晰的撤销动作。取消选择、取消生成、按 Esc 取消拖动及异常失败后，不留下临时块、残留图层、虚假编号或未提交计数。宿主有锁定要求时正确持有并释放文档锁，数据库修改用事务；AutoCAD 官方明确要求在无模式窗口等特定上下文修改文档时处理锁定，普通当前文档命令的锁定条件不同。[A7] 不应把所有操作笼统包在跨线程长时间文档锁内。

## 8. 开发阶段与交付

1. **环境与原块接入**：加载命令成功；绑定原块或明确的据图重建块；24 人名义容量与尺寸通过；单位/UCS 通过。
2. **算法核心**：完成纯数据计算、连接柜组合、边界与碰撞、两侧拓扑、多候选及不足原因；以人工构造反例和固定随机种子回归。
3. **矩形内预览与落图**：至少一种有证据的 S 形形式从输入人数到原生块落图贯通；取消/撤销恢复。
4. **手动编辑**：正交拖动、原生移动复制后重算、实例定位及统计。
5. **三模式联合验收**：12/18/24/48鞋柜、一更12门衣柜、二更工装衣架均须完成自动多候选和编辑落图；房间/性别切换不丢状态、不串用人数或算法。仅鞋柜运行不能算首版交付。

首版安装包、源码、依赖版本、宿主配置、使用说明、示例 DWG 和测试证据都应随本地开发进展交付。图面结果应在真实 CAD 中打开核对，不用浏览器里的近似 SVG 代替宿主验收。本轮交接资料与数学参考计算不代表上述阶段已完成。

## 9. 性能目标（待实测）

先定义用户电脑、宿主版本和测试图纸，再记录中位数与 P95：正常拖动反馈目标 P95 不超过 100 ms；600 人常规矩形首个有效候选目标 2 秒内、全部候选目标 10 秒内；数量较大或约束冲突时显示进度、已搜索数量和可取消状态。上述是初始工程目标，不是已经测得的承诺。低配机器允许渐进校核，最终落图前必须执行完整检查，不能跳过拓扑来达到速度指标。
