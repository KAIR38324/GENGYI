# 首版完整房间模式：换鞋、一更、二更

## 1. 新增要求的优先级

2026-11-17 用户进一步明确：**一更和二更也要有设备，插件必须能切换房间。** 因此首版不是只有鞋柜算法、以后再扩展衣柜与衣架。以下三个模式都必须实现：人数计算、选定房间矩形、自动生成多候选、拖动编辑、实时统计、落图、重新打开和继续编辑。

| 模式 ID | 中文模式 | 首版默认房间实例 | 核心容量设备 |
| --- | --- | --- | --- |
| `shoe` | 换鞋间 | `shoe_shared` | S12／S18／S24／S48 双面鞋柜与原样式转角 |
| `first_change` | 一更 | `male_first`、`female_first` | LOCKER12，12 门个人衣柜 |
| `second_change` | 二更 | `male_second`、`female_second` | HANGER_CUSTOM，按实际挂钩节距计算的工装衣架 |

默认实例表示当前项目的共用换鞋间、男一更、女一更、男二更和女二更。它们是已有功能房的工作对象，**不新增功能房，不把男女合成一个实际更衣空间**。界面可以用“房间类型＋男女子房间”两级切换，也可以用五个明确房间标签。

## 2. 每个房间都有自己的完整状态

房间实例至少保存下列内容：

```text
room_id / mode_id / name / gender
boundary_entity_id / boundary_polygon / local_coordinate_system
door_entities / columns / fixed_obstacles / relevant_boundary_rules
population_basis / people_count / reserve_ratio / target_capacity
equipment_palette / selected_skus / original_block_mapping
candidate_schemes / current_candidate_id / manual_edits
placed_instances / capacity_statistics / area_statistics
validation_results / unresolved_parameters / source_provenance
cad_entity_ids / undo_state_reference / last_saved_revision
```

换到另一个房间时，只改变当前编辑对象；其他房间的柜子、候选方案、手工摆放、人口口径和边界仍然保留。返回原房间必须恢复之前的状态，不能重置成默认矩形、重新随机排列或把别的房间柜数加进来。

当前候选与已落图实体要分开。切换候选可暂时显示预览，但不能自动删除已经落图的设备。用户确认替换一个房间方案时，以该房间为 CAD 事务范围；不能顺带清空另外四个房间。

同一图纸中已落图房间必须保持独立身份。检查房间之间重叠的边界和实际实体冲突，不能因为它们处于不同模式就允许两个房间占用同一物理位置。

## 3. 人数口径与尾数

### 3.1 项目级人数

当前值：在册 600 人、单班峰值 300 人、男女 1:1，备用率 0。班次数仅为上下文，不能把所有输入人数都直接乘二或除二。

界面需明确显示“在册人数”和“单班峰值”两个不同字段。只有一个“人数”而不显示其含义的界面不可验收。自动按班次数推导峰值时，应标为推导、允许独立修改，且不能覆盖用户已明确输入的 300。

### 3.2 男女拆分

先对在册和当班两组整数分别按男女比例拆分，然后按各房间设置备用率。与参考函数 `room_requirements()` 保持一致：

```text
男 = floor(总人数 × 男比例 + 0.5)   # 正数普通四舍五入，恰好 .5 时男优先
女 = 总人数 - 男
房间目标 = ceil(房间基础人数 × (1 + 房间备用率))
```

禁止男女各自独立向上取整，造成总数凭空增加；也不要使用语言默认的银行家舍入替代上述规则。若以后支持用户直接填写男女整数，则其和必须等于对应总人数，界面显示差额。

备用位的向上取整发生在各房间内部，因此启用备用率后，全项目各房间目标之和可能比“总数统一加成一次”多 1 位；这是分房取整，必须显示口径。

### 3.3 可复算示例

下面均为备用率 0，单班峰值为示例中明确输入的值，不是强制由在册人数除二。

| 在册／当班 | 换鞋目标 | 男／女一更人数 | 男／女一更柜数与实际门位 | 男／女二更挂位 |
| --- | ---: | --- | --- | --- |
| 600／300 | 600 | 300／300 | 25 柜 300 位／25 柜 300 位 | 150／150 |
| 500／250 | 500 | 250／250 | 21 柜 252 位／21 柜 252 位 | 125／125 |
| 501／251 | 501 | 251／250 | 21 柜 252 位／21 柜 252 位 | 126／125 |

500 人鞋位若只使用 S24，为 21 柜、504 位；501 人也是 21 柜、504 位。界面应显示离散余量 4／3 人，不能把人数向下改为 480。

## 4. 换鞋模式

沿用 `02_SHOE_GEOMETRY_AND_TOPOLOGY.md` 和 `03_CAPACITY_AND_AREA.md` 的鞋柜规则：在册人数、一人两格、S 形连接、常规边界柜 1000、端部绕行检查、上下叠柜容量与跨柜动作分开。

设备面板提供 S12、S18、S24、S48 与 R600 转角。茶水柜 CUP100 可作为该房间的辅助设备加入并参加碰撞和操作面检查，不增加鞋位。

该模式的 1000 边界条件、脏净双面配对、跨柜转换和 S 形拓扑为**模式专属规则**，不能通过继承公共默认值而不加区分地施加到一更、二更。

## 5. 一更模式：首版必须完整实现

### 5.1 设备与容量

依据原 `07-1794325063428.png`：

```text
LOCKER12 = 1140（长）×500（深）×2095（高）
3列 ×4层 =12门，每人一门
柜数 = ceil(房间目标人数 /12)
```

当前男、女各 300 人，因此各 25 个柜。每个柜投影 0.57 m²，各房间柜体投影为 14.25 m²。**14.25 m² 不是一更房间面积。**

每个衣柜是单面个人柜。背靠背放置两个实体时共 24 人，而不是给一个柜增加一个虚构的使用面。柜门的实际开门尺寸与方向应由原块或厂家图取得。

### 5.2 首版候选家族

- 沿单墙、两面墙或多面墙布置，柜背面朝墙、使用面朝室内；在转角处核查相邻柜门与取物区。
- 背靠背岛柜加沿墙柜，两个柜前方分别提供可达的使用区；柜背之间按真实安装与维护条件设置间距。
- 多列柜排或端部补柜，按人数尾数与矩形长宽重组；方向可旋转 90°，但不能把柜门朝向无法进入的夹缝。

候选先按真实尺寸离散生成，再校验操作面、门、柱和通道。每种可行家族给出不同方案；如果矩形仅容纳一种有效方案，应说明原因，不能为了“多候选”复制旋转后等价的无效结果。

### 5.3 间距规则

一更没有鞋柜的双侧跨越要求。柜背靠墙距离、侧向安装缝、两柜背间距、柜门开启包络、柜前取物与穿脱衣空间分别设参数。

历史方案的“相向柜净距 950”没有完成真实柜门和更衣动作验证，**不能作为已证足够的硬编码常数**。原表门列宽度 1140/3＝380 也只是名义列距，不能替代实测门扇净宽。

数据未知时可以生成明确标为“仅实体几何预排、动作未核”的候选，允许继续编辑和设置参数；不得把未核值暗中设为零并输出可用性通过。参数面板须提示缺的是哪一种安装或操作尺寸。

### 5.4 实时统计

显示本房间基础人数、备用目标、12 门柜已放置数量、名义门位、受阻门位、有效门位、未满足人数和离散余量。拖走一柜使可用门位减少 12，不能套用鞋柜的两面格数逻辑。

## 6. 二更模式：首版必须完整实现

### 6.1 设备、构造与统计

核心设备 HANGER_CUSTOM 来源于 `08-1794325072598.png`。横向管 450、竖向吊杆 650、挂钩节距 100。**650 是构件长度，不是安装离地高度。** 总长按设计，安装标高与支撑位置需保留独立参数。

每个独立挂架段保存总长、两端退距、挂钩间距、挂钩线数与来源、安装方式、安装标高、支撑件、操作侧、实际挂点坐标及所属人数。

单列连续段：

```text
长度 L 必须为正；若 L<a+b，则0位
否则 H=floor((L-a-b)/100)+1
```

暂取两端各 50 是显式规划假设，原表没有给出端距。该假设下：当前男女各 150 位，单连续段各需 15000；选择 10% 备用时各 165 位，单连续段各需 16500。

多段挂架按每段独立扣端距后求和。转角处相邻段不能把同一个挂点计两次；柱、门或断开的缺口不能作为连续挂架长度计位。要统计实际挂点集合，而不只是将整个折线总长除以 100。

### 6.2 首版候选家族

- 沿墙单面挂架，按可用墙段分段，绕开门、镜和柱。
- 中岛挂架，支撑与安装方式明确，实际操作侧可达；单挂钩线默认仍为一列容量。
- 沿墙与中岛组合、多段平行或折返排列，分别核查衣物投影、取挂衣动作与更衣空间。

不能因为人能从两边靠近，或者图上画了两条线，就将同一排挂钩容量乘二。只有存在两套独立、可用、有来源的挂点线，才可计算两列容量。

450 横向管的真实投影方向应由原图块确定；不能无条件把它当所有衣架均有 450 地面深度。吊挂设备的地面无支腿也不意味着其下方可完全忽略衣物和人体活动占用。

### 6.3 原总表中的辅助设备

原 `04-1794325020493.png` 在二更列有更衣镜及紫外线设备，应保留设备条目和待落位状态：

- 更衣镜：原表宽 1400、高 1600、下沿距地 600；按墙面设备检查安装面、视线及使用位置，不增加挂位。
- 紫外线设备：原表安装高度 2200、220 V／15 W；产品尺寸和具体布置方式未给，应从原 CAD 或选型补充，不虚构占地和设备数量。

首版设备面板应能插入、移动并统计这些非容量设备。辅助设备缺少块或数量时显示“待落位”，不能悄悄删除原功能，也不为其新增房间。

### 6.4 实时统计

显示本房间当班人数、目标挂位、挂架段数、总安装长度、实际挂点数、受阻／重复挂点数、有效挂位、未满足人数。区分“还差多少挂位”和“还差多少段”：挂架可定制长度，待放段数不是唯一解。

## 7. 模式切换与规则隔离

### 7.1 切换行为

1. 当前操作未确认时，保留预览状态并提示其尚未落图，不强制提交。
2. 切换房间后恢复该房间的边界、设备工具板、已选候选、统计和规则。
3. 切换回原房间时恢复手工调整；自动生成新方案应作为新候选，不覆盖手工方案。
4. 可以按项目汇总所有房间，但汇总必须分列鞋位、个人柜门位和挂位，不能把不同单位相加为一个“总容量”。
5. 修改项目在册／当班人数或男女比例时，依赖这些值的房间标记“需重新核算”，显示新旧差额；原几何保留。用户确认重新生成后再写入新布局。

### 7.2 共用规则与模式专属规则

| 规则 | 换鞋 | 一更 | 二更 |
| --- | --- | --- | --- |
| 默认人数来源 | 在册总人数 | 在册按性别拆分 | 当班按性别拆分 |
| 容量单位 | 脏净配对鞋位 | 个人柜门位 | 独立挂位 |
| 自动候选 | 连续 S 形及变体 | 沿墙／背靠背／多列 | 沿墙／中岛／多段 |
| 边界条件 | 常规柜 1000 | 按柜背、侧边、使用面分别定义 | 按墙挂、吊挂、支撑及衣物投影定义 |
| 是否强制鞋式分隔拓扑 | 是 | 否 | 否 |
| 是否需要双面配对 | 是 | 否 | 否 |
| 独立操作校验 | 取鞋与跨柜 | 开柜、取物、穿脱衣 | 取挂衣、穿脱衣 |
| 缺失厂家尺寸 | 显示未核 | 显示未核 | 显示未核 |

共用部分是边界/障碍、真实尺寸、原块保真、正交拖动、撤销重做、碰撞、单位、候选保存与 CAD 事务，不是把鞋柜的所有工程条件复制到别的房间。

## 8. 最低首版验收

1. 依次切换五个默认实例，每个实例都能选自己的矩形、生成至少两种不同候选（存在多个可行解时）、拖动设备并落图；不能一更／二更仅展示参数表。
2. 600／300、1:1、0 备用时：鞋 600，男／女一更各 25 柜 300 位，男／女二更各 150 挂位；与参考计算一致。
3. 500／250 和 501／251 两组测试的男女拆分、柜数尾数按本文件示例一致；合计基础人数不增加。
4. 男一更手动旋转并移动一柜，切到女二更生成挂架，再切回男一更，操作结果保留。
5. 男一更删除一柜只影响男一更统计；删除二更一段挂架按该段实际挂点扣除，不固定扣 12 或 24。
6. 一更柜背可以按其独立规则靠墙，不因鞋柜专属 1000 产生错误；柜前动作空间仍单独核查。
7. 二更同一挂钩线即使双面可达也不翻倍；两段交会的同一挂点只计一次。
8. 将项目人数改为更大值后，相关房间状态变为需复核，CAD 中手工布局不被静默重排。
9. CAD 保存关闭再打开，房间标识、实例属性、源块、候选和统计可恢复；识别用户原生 MOVE／ROTATE／ERASE 后及时重算。
10. 任何模式都不能用自画示意图块冒充用户原块；缺块时可提供工程预览，但交付状态应准确说明来源未核。
