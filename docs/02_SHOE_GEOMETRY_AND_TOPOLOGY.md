# 鞋柜模块、S 形连接与脏净分隔

本文件供本地 Codex 实现 CAD 布置引擎。长度统一为 **mm**，面积统一为 **m²**。这里的“原图”仅指 `references/original_images` 中用户上传的图片；历史生成稿不是原图块来源。

## 1. 证据与优先级

1. **2026-11-17 用户最新确认**：一个 24 人双面鞋柜为 2000×600；每面 8 列、每列 3 层；一人分别使用脏侧和净侧各一格。可定制 12、18、24 人柜，可以上下叠两柜形成 48 人柜。采用 S 形，横向和竖向段均可用柜；用连接柜控制排间距；常规边界柜距矩形边界 1000；人员通过跨柜完成脏净转换。
2. `05-1794325039166.png`：标准柜 2000×600×600，304 不锈钢；另列 R600、H600 四分之一圆弧角。表中“24/48”“48 人鞋柜一体形式”存在口径歧义，容量以第 1 条最新明确解释为准。
3. `02-18753.jpg`：原换鞋区局部，能看到多次折返的 S 形、直段分格和圆弧转角。`03-18752.jpg` 是原总平面。
4. 原表“柜门 260×168”与 2000/8＝250 的名义列距不能直接兼容，不能据此自动输出制造门片。图块真实定义、门片净尺寸、分隔板及转角构造仍需由本地原 CAD 或厂家图核定。

**不得用后续 AI 生成 DXF 或所谓“原图符号对比”中的自画符号替代这些证据。**

## 2. 一人两格的容量口径

设每面列数 `c`，每个单层柜的竖向储鞋层数 `r=3`，上下叠柜数 `s`，柜体有两个使用面。

```text
每面格数 = c × r × s
物理总格数 = 2 × c × r × s
服务人数 = 物理总格数 / 2 = c × r × s
```

24 人柜的两个面合计 48 个物理格，服务 **24 人**；不能再把两个面各计 24 人而得到 48 人。

每一人应有一个配对号，关联同一柜、同一列、同一层的两侧格位。例如 `S001-C03-R02-D` 与 `S001-C03-R02-C`。旋转柜子只改变面在平面中的朝向，不改变这两个格位属于同一人的关系。

## 3. 单元格与定制模块尺寸

由用户最新的列层划分推得标准单元的**名义模数**：

```text
列距 = 2000 / 8 = 250
单面分配深度 = 600 / 2 = 300
层距 = 600 / 3 = 200
名义单格 = 250 × 300 × 200（宽×深×高）
```

这些不是净空尺寸。实际净宽要扣框料、侧板、隔板；净深要扣背板、门板与构造余量；净高要扣底板、隔板、座面和支撑。原资料不足以给出扣减后的精确值。不要简单把每个尺寸均减 2 mm 后宣称是厂家净格。

| 类型 ID | 名义服务人数 | 每面列×层 | 物理格总数 | 长×宽×高 | 柜体投影 |
| --- | ---: | --- | ---: | --- | ---: |
| S12 | 12 | 4×3 | 24 | 1000×600×600 | 0.60 m² |
| S18 | 18 | 6×3 | 36 | 1500×600×600 | 0.90 m² |
| S24 | 24 | 8×3 | 48 | 2000×600×600 | 1.20 m² |
| S48 | 48 | 8×6 | 96 | 2000×600×1200 | 1.20 m² |

S12、S18 的长度按保持 250 列距推算；S48 的高度按两个 H600 柜叠置推算。以上三项属于**参数化推导值**，不是已经取得的厂家成品图。实际叠放连接件可能增加总高，应另存 `stack_connector_height_mm`。

S48 在平面上仍为一个 2000×600 的柜组，占地不能重复算两次。其两层分别建库存容量，并保留柜组和上下实体的关联，防止拖动后两层错位或重复计人数。

## 4. 平面图块必须继承原样式

### 4.1 来源与替换

- 当前仅有原方案截图及设备表，没有取得原生设备 BLOCK 定义。截图可作为视觉基准，不能宣称已恢复精确原块。
- 本地 Codex 优先读取用户原 DWG/DXF，识别块名、基点、真实外轮廓、图层、属性、动态参数、嵌套和单位；必要时让用户在图上点选一个代表块。
- 把“CAD 图块形象”和“求解器几何”分开：前者保持原样式，后者使用真实占地多边形、操作面和连接端口。外包矩形只能用于快速筛选。
- 自定义 12/18 人变体应按原符号单元阵列、真实端板和连接件生成，或者使用已核定动态块参数。禁止将 2000 长的标准块整体缩放成 1000/1500，导致格宽、柜深、线型和细节一并失真。
- 三层是竖向层数。不要把三层门格当作平面深度方向的三排来绘制。平面细线以原始 CAD 为准。
- 默认正交角度为 0°、90°、180°、270°。镜像须单独处理脏净面与文字，不可用负比例静默翻转编号。

### 4.2 必须保存的模块字段

```text
instance_id / assembly_id / module_type
cad_block_name / source_file / source_verified / source_hash
length_mm / depth_mm / height_mm / column_count / row_count / stack_count
nominal_people / physical_cells / valid_pair_capacity / assigned_people
insertion_point / rotation_deg / scale / footprint_polygon
dirty_face / clean_face / operation_zones / connector_ports
boundary_clearance_mm / validation_status / diagnostics
```

应把 `nominal_people` 与 `valid_pair_capacity` 分开。柜子画得下，不代表两个使用面都能到达和取鞋。

## 5. S 形不能简化为几排互不相关的矩形

### 5.1 从原方案保留的形式

原图显示连续折返、两侧分格、竖向连接以及圆弧转角。生成器应先形成柜链或柜网，再为每个实体选实际模块。转角、竖段、横段都参与碰撞、操作面和容量验证。

R600 圆弧角在原参数表中单列。没有储鞋格位资料时，其默认服务人数为 **0**，不能按占地折算为鞋位。几何上保留转角轮廓；不能用两柜 600×600 重叠来假装已做圆弧转角。

### 5.2 连接长度与排间净距

两排平行横柜的深度均为 `w=600`，相邻两排靠近的外边线之间净距为 `g`。竖柜沿其长度方向连接两排。

| 接法 | 几何关系示例 | 必须检查 |
| --- | --- | --- |
| 竖段仅占两排内侧边之间的空档 | `L竖 = g` | 若柜端直接顶住横柜的长边，会挡住横柜柜门；零重叠仍可能损失有效容量 |
| 竖段跨越两排整个外侧总深 | `L竖 = g + 2w` | 需裁定两排横柜的终点及竖柜长边被遮挡的长度，不能让两柜穿插重叠 |
| 经原生转角块连接的切线端口 | `g` 由端口坐标、转角块和竖柜长度共同确定 | 若经核实的 R600 转角使竖柜端口正好位于两横排内侧边，则可出现 `g=L竖`；不能在导入前把该等式写死 |

因此，S12/S18/S24 可产生不同档位的连接长度，但不能不看接法就认定“12 人竖柜必然对应 1000 净距”。原生块端口的变换后坐标才是最终依据。

引擎应保存连接类型、连接端口和邻接对象；拖动一个连接柜后，关联横排或整段柜链随约束更新。若用户解除连接单独拖动，立即重新验证分隔与容量。

### 5.3 接触与碰撞的判定

- 两柜可在核定的接合边接触；内部面积重叠为错误。
- 允许数值容差不等于允许施工缝隙。计算容差、安装缝、封板宽度分别建参数。
- 对弧形件使用曲线或经公差控制的轮廓多边形，不把整块外包矩形都当实心，也不把弧边空缺忽略。
- 使用面被柜体、转角件或墙遮挡时，对该面格位进行逐列扣减；配对容量取两面均可使用且可正确配对的格位集合。
- 同一位置上下叠柜允许投影重合，但属于同一柜组。不同柜组的投影重叠仍为碰撞。

## 6. 1000 边界距离与“只能跨柜”的联合约束

用户要求的是**日常换鞋的脏净分隔**。本节不增加应急走道或应急开口。

### 6.1 边界距离

常规边界柜至所选矩形内边界的净距离默认 1000。矩形须先转换为项目局部正交坐标，距离用真实柜体轮廓求取，不能只量插入点或中心点。数值可在界面显示为目标 1000、实际最小距离及差值。

“其他边界柜”所指的例外端部尚未形成逐点规则。生成器不得自行把某个柜标为例外并贴墙；若原图存在边界连接端，应由本地原图识别为明确端口，显示其依据与连接件。没有明确例外时，所有常规边界柜均执行 1000。

### 6.2 一个必须显式处理的几何冲突

**开放的 S 形柜链如果整体位于矩形内部，而且四周留出连续 1000 空带，通常可以从柜链端部绕到另一侧。** 这种候选不能同时声称满足“只能跨柜”。

可行性必须依赖明确的实体和边界关系，例如原有墙、固定封板、封闭端部、经核定的闭合柜链，或者原方案已存在的分隔连接。若使用固定封板跨越边界空带，必须作为真实阻隔实体显示、统计，柜体本身仍满足所要求的距墙净距。不能把“从图上看似封住”当作已经封闭。

如果选中的矩形没有任何可用分隔边界，而用户又禁止增加或使用端部阻隔，求解器应返回：

> 可装下目标鞋位，但当前开放 S 形允许绕端，未满足只能跨柜；需选定原有分隔连接或调整柜链端部方案。

这不是要求再增加走道。失败原因是脏净两侧的连通关系未成立。

### 6.3 推荐验证算法

1. 构造区域 `R`：选中矩形，减墙、柱、柜体、固定封板和已核定的其他阻隔。
2. 分别输入脏侧入口种子和净侧出口种子。默认从用户点选门或区域入口取得，不凭“上/下”猜测。
3. **不启用跨柜边**时，检查脏侧种子与净侧种子是否位于不同的可行走连通分量；若相同，输出绕行路径并标红。
4. 检查每个有效鞋位的脏侧操作区可由脏侧种子到达，净侧操作区可由净侧种子到达。竖向连接柜也必须做双侧可达检查。
5. 再加入用户允许的跨柜转换边，确认整体使用流程连通。转换边连接指定柜两侧操作区，不能任意穿过墙、柱、叠柜或转角。
6. 用指定人员宽度或操作包络验证通行。网格洪泛可以做交互预检，但最终应有几何连通验证，且不能因网格过粗漏掉端部开口。给出分辨率和误差。
7. 拖动、旋转、删除、换型、增减叠层或修改矩形后，所有相关结论失效并重新计算。

狭缝不能仅因“人宽膨胀后不连通”就被认定为卫生封闭；几何阻隔、可步行绕行及实际封闭构造应分别显示。

### 6.4 叠柜与跨柜动作分开建模

S48 可以提供 48 人名义配对储鞋容量，但上下叠置后的高度约 1200。不能仅根据平面占地相同，就把它当成与 H600 低柜一样的跨坐转换位置。

默认模型把 `storage_capacity` 和 `crossing_enabled` 分开。低柜的跨柜方式按用户现行操作建立；叠柜的容量可在两面取放可达条件下保留，跨柜路径可使用附近指定低柜。不要把“没有在叠柜本体跨越”误算成该叠柜必然没有储鞋容量，也不要自动把 H1200 设置为可跨。

## 7. 手工拖动必须实时保留的工程含义

- 默认正交与端口捕捉；屏幕拖动仅为预览，确认落点才写入 CAD 事务。
- 实时显示几何占用、边界净距、最窄可达处、绕行是否存在、有效容量及未满足人数。
- 允许自由摆放以便设计探索；无效位置以红色和具体原因显示，不能因为满足人数就标为方案通过。
- 拖动后生成的尺寸仍须是可重算的工程尺寸，不能是固定文字。
- 输出 CAD 时保留原设备块参照、属性与图层；房间/边界、设备、尺寸、文字、脏净分区、诊断和分析辅助层应可独立控制。

## 8. 最低验收样例

| 样例 | 预期 |
| --- | --- |
| S24 两面各 8×3 格 | 24 人、48 物理格，绝不为 48 人 |
| S12 + S18 + S24 | 54 人，柜体直段总长 4500、投影 2.70 m² |
| 一个 S48 柜组 | 48 人、96 格、投影 1.20 m²；低柜跨越位置不能重复计入 |
| 开放 S 形四周连续 1000 空带 | 必须检测到绕端，不能输出“只能跨柜已满足” |
| 竖柜端部抵住横柜柜门 | 面接触可成立，但被挡格位不能计有效容量 |
| 删除一个端部封板 | 从通过立即变为可绕行，并显示具体绕行路径 |
| 旋转 90° 的连接柜 | 双侧方向、操作区、配对编号和端口同步旋转 |

| 移动一个 S48 柜组 | 上下实体同步移动，容量和投影不重复 |
